# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

枫叶小屋的工具箱 (shuxia-toolbox) — a WeChat mini-program toolbox. Tools: 拼豆图纸生成器 (image → bead grid + per-color counts) and 旅游攻略图生成器 (origin + destination + travel-mode → AI-planned trip → **multiple independent 小红书 cards** + copy-paste caption; places tagged sight/food/stay/shop/transit).

Key design decision: image processing (拼豆) runs **client-side** via Canvas (no image upload) to reduce privacy/audit risk. The 旅游攻略 tool is the **backend-consuming** tool — it calls `POST /api/travel/plan` (AI itinerary + geocode + directions + two staticMaps) and `GET /api/travel/geocode` (Tencent-map suggestion proxy behind a `MapProvider` interface, swappable to Amap). Output is **not one long image** but a set of independent 1080×1440 (3:4) 小红书 cards — 路线规划图(真实/示意) / 景点分布图 / 美食推荐图 / 行程时间线 — each individually saved to album, plus an AI-generated 小红书 caption (title/body/tags) with one-click copy. Cards are Canvas-composited (crisp Chinese text) with a procedural "手绘水彩" theme (`utils/guide/theme.ts` — no external PNG assets, no image-gen); real-map cards overlay Tencent staticMap. Frontend `API_BASE` constant (in `useTravelEditor.ts`) points at the backend; note the dev container's 9501 is **not** mapped to the host, so reaching it requires port mapping or an exposed backend URL + WeChat legal-domain config.

## Architecture

### Frontend — uni-app + Vue 3 + Vite + TypeScript

- Page routing via `src/pages.json` (uni-app convention, no vue-router): `pages/home/index` (toolbox home) and `pages/beads/index` (bead generator).
- No Pinia/Vuex. State lives in composables under `src/composables/`:
  - `useBeadPattern.ts` — the pattern pipeline (`generatePattern`): (1) optional pixel-level background removal (`removeSourceBackgroundFlood`) — edge-color flood from the 4 borders; for near-neutral (white/gray) backgrounds it also clears near-neutral, luminance-similar pixels to handle noisy/compressed backgrounds, and an inward-depth check bails when the candidate is only a thin outline/border so frame-filling stickers' outlines aren't deleted; (2) crop — transparent-margin crop only (`detectOpaqueCrop`), else full image (no "colorful subject" crop: it dropped non-colorful subjects like a white panda and warped aspect ratio); (3) downsample — per cell, if one color is the majority (>50% of the cell) use that **dominant color** (crisp boundaries, no muddy blend — more detail per bead at the same count), else the alpha-weighted area average (smooth gradients/photos don't get noisy). `auto` sizes **by content complexity, not pixels**: it measures the image's dominant structural colors (area-average to ref 80, **2-bit quantize** so anti-aliasing/JPEG noise merges back into the flat colors instead of inflating the count, count colors >1%) **plus an edge-density factor** (fraction of non-empty cells whose color differs sharply from a 4-neighbor — captures thin-line/many-part complexity that the color count misses) and sets long side = `clamp(38 + colors×0.6 + edgeDensity×80, 38, 64)`, capped at `min(that, sourceLong)` (small images aren't upscaled). The floor of 38 ensures low-color images (a single-character emoji) still get enough cells to keep detail; cap is 64 — raised from 52 because line-dense subjects (a panda riding a tricycle: few colors but dense outlines/spokes/frame) need ~62 cells to resolve sub-cell features that otherwise blob into solid dark; pure-color/gradient images have edgeDensity≈0 and stay at 38-45 (unaffected). Simple images ~1.5-2k beads / 1 small board; complex line-dense images ~2-2.5k beads / 1 big (104) board. board-preset/custom override; **detail preservation**: a cell crossed by a thin feature (dark outline, colored text/strokes) would average to a washed-out transition color (outlines break, text becomes illegible). The fix is directional, not RGB-distance (a two-color cell averages between the two, so both colors are "far from average" and cancel out): the dark rule **binarises** outline edges by `darkShare` (the cell's dark-pixel alpha share — robust to anti-aliasing because it sums all luma<90 pixels regardless of palette fragmentation): a cell snaps to the dark color when `darkShare ≥ DARK_MIN_SHARE=0.35` (the outline covers the cell); a low-`darkShare` "graze" cell (outline only clips a corner) takes the **non-dark average** — dark pixels excluded — so it becomes the pure fill, never a mid-tone. This is the key anti-杂色 measure: averaging dark+fill in non-dominant edge cells produces a scatter of distinct mid-tone palette colors along the curve that reads exactly as 杂色+jaggies, so outline edges are forced binary (dark or fill), never averaged. Smoother curves come from more cells / higher resolution, not from transition colors. A chroma gate remains on the snap: if the cell average is already clearly chromatic (avgChroma>50) and dark is a minority (<50%), the dark is bleed from an adjacent outline, not the cell's own feature — keep the color, don't snap dark, or a small colored region ringed by dark (e.g. the pink tongue inside an open mouth) gets eaten into solid black ring-by-ring. High-saturation minorities much more *saturated* than the cell average keep the saturated color (text/strokes stay legible); (4) per-cell **direct** ΔE2000 nearest-palette mapping (`mapCellsDirectToPalette` → `nearestBeadIndex`); (5) merge low-frequency colors (share <1%) within ΔE2000<16 into more common ones (`mergeSimilarColorsByFrequency`) to collapse anti-aliasing fragmentation — at 16 (raised from 12) the dark-red/gray-purple/brown transition specks along outlines get pulled back into the main outline color so borders stay continuous instead of speckled (worse at higher resolution where edge cells multiply), while independent semantic detail (e.g. a wheel's yellow-green spokes, ΔE>16 from every high-freq color) survives because merge only folds *near* colors; (5b) **dark-outline consolidation** (`consolidateDarkOutline`) — folds **all** *dark* colors (luma≤112) into the single most-frequent dark, **no ΔE limit**, regardless of share. This is separate from (5) because a dark outline gets split across 5+ beads (dark-red/gray-purple/brown, each >1% share so (5) skips them) and the user sees a speckled border; the AA fragments span large ΔE (>20) by *hue* (red↔purple↔brown), so a ΔE threshold always misses half of them — the reliable signal is that they are all dark, so every dark merges into the dominant one. It is luma-gated (not global) so light skin/blush (ΔE~5 but luma>112) are untouched. Near-black sources (luma<55) are protected so pupils/eyes don't fold into mid-dark gray; cost: any other same-darkness element also merges into the outline color (fine for single-subject stickers/cartoons); (6) connected-component despeckle (regions ≤3 cells → neighbor majority, iterated to fixed point); (7) color counts. There is **no k-means / quantize-then-map** — direct per-cell mapping on the *downsampled* grid is intentional (downsampling pre-averages, so flat areas stay clean and photo gradients are preserved); the color-merge + despeckle steps are what suppress noise. Tunable params: `boardPresetKey / paletteKey / removeBackground` plus `autoGridSize` + `gridLongSide` (in `auto` board mode: `autoGridSize=true` uses the content-adaptive sizing above; `false` lets the user manually set the long side 30-104 via a slider — auto-sizing is unreliable for some image types like a vehicle with many small parts, so manual override exists for those). `removeBackground` defaults **on** (most inputs are stickers/emoji on a flat background the user wants gone; changed from off — note the tradeoff: removing the background of a light/white subject on a *colored* background can destroy the contrast that makes it visible, so it remains a user-toggleable param); merge threshold is a code constant.
  - `useBeadCanvas.ts` — on-page preview (zoom by re-render at 1x/2x/3x inside a scroll-view); `useBeadExport.ts` — high-res export + save-to-album with permission-denied → openSetting flow.
- `src/utils/sheetRenderer.ts` — shared by preview and export (preview is exactly what gets exported): title `Mard(total)`, row/column indices on all four edges, per-cell color codes with auto black/white text, checkerboard empty cells, legend pills. All dimensions are ratios of `cellPx`; total canvas is capped at 4000px (iOS canvas limit), falling back to 2800px on export failure.
- `src/utils/canvasAdapter.ts` — the only file with `#ifdef MP-WEIXIN` / `#ifdef H5` conditional compilation; both branches must typecheck (vue-tsc sees both).
- `src/utils/beadPalette.ts` + `beadPaletteData.ts` — palette data (RGB, ported from PHP; LAB computed lazily at runtime) and ΔE2000 nearest-color matching. Default palette key: `mard-221`. Color codes are zero-padded in data (`F04`); strip via `displayCode()` only at render time (`F4`).
- `@/` aliases `src/`.

### Backend — PHP 8.4 + Hyperf 3.2 (beta) on Swoole

- Entry point `bin/hyperf.php`; Swoole HTTP server on port 9501 (env `SERVER_PORT`).
- Routes defined in `config/routes.php`: `GET /health`, `GET /api/health`, `GET /api/beads/palettes`, `POST /api/beads/estimate`, `GET /api/travel/geocode` (Tencent suggestion proxy), `POST /api/travel/plan` (the main 旅游攻略 route). `plan` input: `origin`(可选)/`destination`/`travel_mode`(walking|cycling|driving|transit)/`days`/`daily_hours`/`preferences`. `plan` output: `{title, days[stops{...,lng,lat,travelToNext}], food[{name,shop,dishes,note}], tips[], xhs{title,body,tags}, routeMapImage, poiMapImage}`.
- Response envelope: `{code, message, data}` with code 0 = success, 422 = validation error.
- `app/Service/BeadPaletteService.php` holds hard-coded palettes (`basic-24`, `mard-291`, and `mard-221` derived from MARD by filtering prefix groups A–H,M).
- **Database** — MySQL via `hyperf/db-connection` + `hyperf/database` (Laravel-derived Eloquent ORM + Swoole connection pool). Connection config: `config/autoload/databases.php` (`default` pool, `DB_*` env). Models in `app/Model/` (`WechatUser`, `UserSession`, `FoodRoom`, `FoodPoolItem`, `FoodHistory`) extend a project `App\Model\Model` base (`dateFormat = Y-m-d H:i:s`). Schema is created by **migrations** in `migrations/` (run `php bin/hyperf.php migrate` in-container), not runtime auto-DDL. Migration/model/seeder commands are registered in `config/config.php`'s `commands` key (hyperf/database ships no ConfigProvider, so they must be listed explicitly; also requires `hyperf/command`). `FoodRoom.payload` uses the `array` cast (JSON auto encode/decode); services set explicit timestamps only where the model disables auto-timestamps (`UserSession`/`FoodHistory` have no `updated_at`).
- **DB network gotcha**: `dev-mysql` and the `php84-fpm` container are on **different Docker networks** by default, so `dev-mysql` resolves to a proxy IP (198.18.x) that corrupts the MySQL greeting → `SQLSTATE[HY000] [2006] MySQL server has gone away`. Fix: `docker network connect development_default php84-fpm` (puts php84 on MySQL's network so Docker DNS resolves `dev-mysql`→192.168.147.x directly). Persist by adding php84-fpm to that network in compose.
- Middleware: `ApiKeyMiddleware` (X-API-Key) + `#[RateLimit]`. Auth: WeChat `wx.login` code→openid→backend token (`X-User-Token`), sessions in `user_sessions`. `config/autoload/wechat.php` holds mini-program credentials (`WECHAT_MINI_APPID`/`WECHAT_MINI_SECRET` from env).
- **全局 AI 功能开关**（个人主体不能提供深度合成服务的合规手段）: `app_configs` 表 `feature.ai_enabled`（默认 `0`），`FeatureFlagService::requireAiEnabled()` 在所有 AI 接口入口硬拦截（灵签 interpret、旅游 plan/refineDay/replaceStop），**不能只靠前端隐藏入口**。公开只读 `GET /api/config/features`，运营台读写 `GET/POST /api/admin/features`（与工具上架同一套 AdminAccessService 鉴权）。前端 `useFeatures.ts` 模块级 ref（默认关=安全默认，拉取失败保持关），灵签页隐藏 AI 解签块、旅游页整页替换为维护提示、运营台有总开关。**注意**：改了带 `#[RateLimit]` 注解的 Controller 后，光重启 hyperf 不够——`runtime/container/proxy/` 的 DI 代理缓存是旧的，必须 `rm -rf runtime/container` 再重启，否则新代码静默不执行。
- Travel service chain: `TravelController`→`TravelService`→`MapProvider` + `AiProvider`. `TravelService::plan` = AI itinerary (`ZhipuProvider`, glm-5.2, web_search on, thinking disabled — one call returns title/days/food/tips/xhs) + best-effort per-stop geocode + adjacent-stop `directions` (mode-mapped) + two staticMaps (`routeMapImage` markers+paths, `poiMapImage` markers-only). Interfaces bound in `config/autoload/dependencies.php` (swap Amap/OpenAI = one line + a Provider class). Uses Tencent **suggestion** (`/ws/place/v1/suggestion`, not geocoder — the dev key has only suggestion enabled) over **HTTP** (Swoole lacks openssl). Guzzle is the only HTTP client.
- **Travel-mode / directions constraint**: Tencent `directions` supports walking/cycling/driving only; **transit is NOT supported** → `plan` maps `transit`→driving for time estimation while keeping the user's original `transit` mode on `travelToNext.mode` (so the frontend shows the 公交 icon). 缆车/索道 also unsupported — AI writes those into stop `note` only. The `MapProvider::explore`周边搜索 is **unused by travel** (that key's `place/v1/explore` endpoint ignores the `keyword` param entirely — even `keyword=火锅`/`category=美食` returns the same generic nearby residential POIs; travel's 美食 comes from AI `food` instead). **But the 吃饭决策器 tool DOES use `explore()`** — so `TencentMapProvider::explore()` routes to `place/v1/search` (keyword + `boundary=nearby`) instead, which honors the keyword (returns real `[美食:火锅]` POIs). Both endpoints share the same `data[]`/`title`/`_distance`/`location` shape, so the one method serves both callers; don't switch it back to `explore` or keyword filtering silently breaks.
- **吃饭决策器 dual-source POI merge**: single-map POI coverage is incomplete (e.g. Amap's Web service doesn't return 「粉小主蜀山万象汇店」, Tencent does), so `FoodController::exploreMerged()` queries **both** the primary `MapProvider` (`MAP_PROVIDER`, prod=amap) **and** Tencent (`new TencentMapProvider()->explore()`) whenever the primary isn't already Tencent + `TENCENT_MAP_KEY` is set, then merges. Both `explore()` return the identical `{name,address,distanceM,lat,lng,category,typecode}` shape (both carry distance), so merging is just concat → `dedupeNearbyItems()` → distance sort. **Only one source needs to succeed** (both fail → throw). `dedupeNearbyItems` keys by 「normalized name (strip `(…)` branch suffix + `·・•`/whitespace) + 3-decimal coords (~100m)」, keeping the closer distance/coords but the more specific name (with branch suffix) and longer address. Consumers: `nearby` (今天随机) and the 附近-search portion of `searchShops` (both go through `exploreMerged`); the frontend 附近-tab place search (`searchPlace` in `useTravelEditor`/food page) now hits `/api/food/search-shops` (was `/api/travel/geocode`, which returned national same-name POIs) with device GPS so results are city-correct + near-first. **Radius overshoot gotcha**: Tencent `place/v1/search` `boundary=nearby(lat,lng,radius)` **auto-expands** when few in-radius results (progressively 1/2/5km up to whole city) → returns POIs far beyond the requested radius (a 3km request returned 20km stores, so 今天随机 could pick a store 20km away). Fix: pass `auto_extend=0` as the **4th arg inside** `nearby(lat,lng,radius,0)` (NOT a separate query param), plus a defensive `distanceM ≤ radius×1.2` filter in `exploreMerged` as a backstop for either map overshooting.
- **Swoole hook flags** (`bin/hyperf.php`): `SWOOLE_HOOK_ALL ^ SWOOLE_HOOK_SOCKETS ^ SWOOLE_HOOK_CURL`. `SWOOLE_HOOK_CURL` is disabled because Swoole's curl hook breaks Guzzle (curl option 20312) and Tencent rejects Guzzle's StreamHandler (status 121); disabling it routes Guzzle through the native PHP curl ext (= system libcurl), behaving like shell curl. Trade-off: curl calls block the worker (acceptable — geocode is the only curl user, low frequency). Tencent key requires per-key **quota allocation** in the console or calls return status 121.
- **工具分类（category）**: `tool_catalog.category` 区分 `tool`/`game`（gomoku 是 game）。底部导航 4 tab：首页/工具箱/游戏/我的（`AppBottomNav.vue`）；工具箱页只列 tool，游戏页（`pages/games/index`）只列 game；首页工具管理和工具运营台按分类分组展示，运营台排序在同分类相邻项间交换（sort_order 仍全局）。新工具上架必须在迁移的 tool_catalog upsert 里带 `category`。
- **联机五子棋（gomoku）**: `POST/GET /api/gomoku/room…`（create/join/state/move/rematch/leave）。混合架构：对局变更走 HTTP（`GomokuRoomService` 服务端权威，事务+行锁，状态存 `gomoku_rooms` 表，重启不丢局），**WebSocket 只做状态推送**——`config/autoload/server.php` 有第二个 server `ws`（`SERVER_WEBSOCKET`，端口 `WS_SERVER_PORT ?: 9502`），路由 `Router::addServer('ws')` → `GomokuWsController`（握手鉴权走 query：`?apiKey=&token=&code=`，因为 wx.connectSocket 的 header 在部分平台不生效）；`GomokuWsPusher` 用**静态**内存表存 code→fd 连接表（Hyperf 构造注入每次新实例，静态才能共享；worker_num=1 所以安全）。每个写操作提交后按房间内每个 fd 对应用户视角逐个推送完整 state（myRole 不同）。前端 `useGomokuRoom.ts`：WS 优先，连续 3 次连接失败或断开降级为 `state?since=version` 轮询（onShow 启动/onHide 停止）。规则引擎 PHP `GomokuRule` 与 TS `utils/gomoku.ts` 平行实现（后端权威，TS 只做即时反馈+单测）。**Hyperf WS 契约接口参数是无类型的**（`onOpen($server, $request)`），实现里加 Swoole 类型声明会 fatal。**部署前置**：容器映射 9502、生产 nginx `location /gomoku/ws` 加 upgrade 反代到 9502（复用同域名）、微信公众平台 socket 合法域名加 `wss://shuxia.lqy-comic.com`。
- **联机 UNO/枫趣牌局（uno）**: `POST/GET /api/uno/room…`（create/join/state/start/play/draw/pass/challenge/declare-uno/catch-uno/rematch/leave）。**对外品牌名是「枫趣牌局」**（UNO 是 Mattel 商标，游戏名不出现 UNO 字样；游戏内机制保留「喊 UNO」叫法——用户拍板。tool_key/路由/代码标识仍用 uno）。品牌色板：奶油白 `#FFF8ED` / 墨绿 `#21483D` / 枫叶红 `#E85D4A` / 金黄 `#F4B942`，图标 `/static/icons/uno-1.png`（用户选定的设计稿推荐方案；另存 Q 版小精灵候选 `fengqu-paiju.png`，生成器 `docs/uno-icon.html`，headless Chrome 截图出图）。同一套混合架构（`UnoRoomService` 权威 + `UnoWsPusher` 推送 + 前端 `useUnoRoom.ts` 轮询降级），三个 UNO 特有设计：
  1. **隐藏信息**：`uno_rooms.state` JSON 存完整对局快照（deck/各人手牌/discard/direction/currentSeat/pendingWild4/unoVulnerable/idleStrikes/leftSeats/scores/lastEvent），`serialize()` 按请求者视角裁剪——`myHand` 只给本人、他人只给 `handCount`、deck 只给 `deckCount`。卡牌编码两字符：颜色 r/g/b/y + 面值 0-9/S/R/D，百搭 wW/wF。
  2. **回合超时主动推进**（gomoku 只有懒过期，但 WS 模式下客户端不轮询）：`turn_deadline_at` 列 + `App\Listener\UnoTurnSweepListener`（听 `MainWorkerStart`——Hyperf 3.x **没有** OnWorkerStart 事件，是 Main/OtherWorkerStart 之分；`Hyperf\Coordinator\Timer::tick(1s)` 自动在协程里跑回调）扫到期房间 `sweepDueRooms()`。**写操作前的懒检查必须传请求者 userId**——若到期的正是请求者本人则刷新 deadline 放行，否则「懒推进→422 回滚→再请求再推进」会把活跃玩家软锁在 422 循环。时限：出牌 20s / 质疑 10s / 挂机 5s（连续 3 次超时进挂机，真实操作解除）。
  3. **规则要点（官方 + 用户定的村规）**：2 人局 reverse=skip（方向恒翻，UI 有反馈）；**+2/+4 可叠加**（村规）：出 +2/+4 不立即罚摸，累计进 `drawStack`，下家只能出任意颜色 +2/+4 续叠或点牌堆全摸跳过（`stack_draw`），叠加出的 +4 不可质疑；**裸 +4 的质疑窗口内，被 +4 者可出 +2/+4 反击——转换为叠加（count=4 起）、质疑窗口关闭**；非叠加的 +4 可质疑也可 `decline-challenge` 主动不质疑（摸 4 跳过）；摸牌玩家自主（有牌可出也可摸），摸完本轮可出任意能出的牌（不限于摸到的，`drawnCard` 仅作前端「新」标记），也可 `pass` 直接放弃本轮；非叠加 +4 质疑成立出 +4 者改摸 4，不成立质疑者摸 6；首张翻出变色牌由首位玩家 `choose-color` 选色开局（超时随机）；剩 1 张未喊 UNO 置 `unoVulnerable`（自喊宽限后他人可举报罚 2，下家任何行动结束窗口）；以 +2/+4 收尾获胜下家仍须先摸累计牌再计分；胜者收全场手牌分（功能 20/百搭 50）累计进房间 `scores`。前端有 `lastEvent` 驱动的全员动作播报条 + 音效（`utils/unoSound.ts`）；房间内可完善微信昵称头像（chooseAvatar + type=nickname，复用 saveUserProfile/uploadAvatar）。**手牌展示自动理牌**：前端 `utils/uno.ts sortHand()`（同色归堆 春绿→夏红→秋黄→冬蓝→百搭，色内 0-9→S/R/D），纯展示层，后端手牌顺序不动（出牌按牌码提交）。

- **联机飞行棋（ludo）**: `POST/GET /api/ludo/room…`（create/join/state/start/roll/move/auto/rematch/leave）。同一套混合架构（`LudoRoomService` 权威 + `LudoWsPusher` 推送 + 前端 `useLudoRoom.ts` 轮询降级 + `LudoTurnSweepListener` 1s 清扫），飞行棋特有设计：

  3. **规则引擎两个修过的坑**（TS/PHP 双份同修，测试锁定）：`pickAuto` 启发式得分初值必须 `INT_MIN`/`-Infinity`——反弹走法前进量为负（55 掷 5 → to=52 得分 −3），初值 −1 会让唯一走法是反弹时返回 null → 自动走子选 0 号机 → 非法走法；`resolveMove` 对 `pos===56`（已到终点）必须返回 null，否则完成机还能走反弹步被拉回来（永不终局死循环，万局模糊测试抓的）。

### Cross-cutting concern

**静态资源走七牛云 CDN**：小程序包内不打包任何图片/音频（主包 1002→713KB、ludo 分包 785→28KB）。资源唯一本地副本在 `frontend/cdn-assets/`（git 跟踪，目录结构 = CDN key 结构），上传/更新跑 `python3 frontend/scripts/upload_qiniu.py`（凭证在 `frontend/.qiniu.env`，已 gitignore；HEAD 大小一致自动跳过，`--force` 强制覆盖）。代码引用一律走 `src/utils/cdn.ts` 的 `cdnUrl('/static/icons/uno-1.png')` → `https://oss.lqy-comic.com/fengye/static/icons/uno-1.png`（bucket=fengye，前缀 fengye，华东-浙江 z0，公开空间）。`tool_catalog.icon` 迁移 `2026_08_31_000025` 已把 uno/ludo 图标改成完整 CDN URL（icon 列扩到 varchar(255)），`ToolIcon.vue` 支持 http(s) 图标。**微信公众平台 downloadFile 合法域名必须包含 `https://oss.lqy-comic.com`**。canvas 贴图用 `canvasAdapter.loadDrawableImage`（远程图自动 wx.downloadFile 缓存）；音效 InnerAudioContext 直接播 https。飞行棋素材重切脚本输出目录也改为 `cdn-assets/`。
