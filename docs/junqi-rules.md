## 1. 棋盘

- 显示坐标 **12 行 × 5 列**（r 0..11 自上而下，c 0..4 自左而右）。行 0–5 为蓝方半场（蓝在后端永远坐上方），行 6–11 为红方半场，行 5/6 之间是「山界」带。
- 每方自身坐标 (ownRow 1..6, col 0..4)：ownRow 1 = 底线（大本营行），6 = 前线。
  - 蓝方（上方）显示行 = ownRow − 1；红方（下方）显示行 = 12 − ownRow。
- **行营 ×5/方**（进入免战，不可被攻击；布阵不可放子）：own (3,1) (3,3) (4,2) (5,1) (5,3) → 蓝显示 (2,1) (2,3) (3,2) (4,1) (4,3)，红显示 (9,1) (9,3) (8,2) (7,1) (7,3)。
- **大本营 ×2/方**（军旗限放于此；任何棋子进入大本营后不能再移动）：own (1,1) (1,3) → 蓝显示 (0,1) (0,3)，红显示 (11,1) (11,3)。

### 1.1 连通边

- **公路**：全图正交相邻边；山界中路（显示 (5,2)↔(6,2)）；每个行营与其 4 个对角格的斜线（仅行营参与斜线，普通格间不能斜走）。
- **铁路**：
  - 横线：显示行 **1、5、6、10** 全宽（c 0..4）
  - 纵线：显示列 **0、4**，行 1..10 连续（含跨山界 (5,0)↔(6,0) 与 (5,4)↔(6,4) 两条铁路通路）
  - 山界第三条通路 (5,2)↔(6,2) 是**公路**（铁路不通中路）
- 铁路格集合 = 上述铁路线上的所有格。

## 3. 布阵（status `layout`）

- 双方各自把 25 子放上己方半场 25 格（30 格 − 5 行营）。约束：
  1. 每格至多一子，行营不可放子
  2. `lei` 只能放己方后两排（红显示行 10/11，蓝显示行 0/1）
  3. `zha` 不可放己方前排（红显示行 6，蓝显示行 5）
  4. `qi` 只能放大本营（红 (11,1)/(11,3)，蓝 (0,1)/(0,3)）
- 前端提供 3 套预设阵型 + 随机合法布阵 + 清空；预设只存前端（`src/utils/junqi.ts`），服务端只按上述约束校验最终阵型。
- 布阵限时 **300 秒**，超时清扫器对未就绪一方自动随机合法布阵。
- 双方就绪 → 进入猜拳。布阵阶段双方阵型互不可见（serialize 只给对方「已就绪」布尔）。

## 4. 猜拳定先手（status `rps`）

- 照斗兽棋家法：双方暗出一拳（r石头/p布/s剪刀），10 秒窗口；双方到齐即结算，a 胜 b ⟺ (a−b+3) mod 3 == 1；平局亮上轮拳重出，上限 3 轮后随机定。
- **无选边步骤、不交换座位**：胜者先行（`turn` 直接设为胜者的座位色），红蓝只是上下半场的座位标签。
- 超时清扫器代未出者随机出拳。

## 5. 走子（status `playing`）

- 不可移动：`lei`、`qi`、位于任一大本营内的棋子（进入后锁足）。
- **公路**：沿边一步一格（含行营斜线一步）。
- **铁路直线**：非工兵在铁路格上可沿所属铁路线直线滑行任意远，路径中间不可有子。
- **工兵铁路**：沿铁路网 BFS 任意拐弯，路径中间格必须为空。
- 落点规则：
  - 己方子占据 → 不可
  - 空格 → 可
  - 敌子占据且该格是**行营** → 不可（行营免战）
  - 敌子占据 → 可（战斗结果由服务器裁决，暗棋下允许攻击任意敌子）
  - 己方大本营 → 不可；敌方大本营空格 → 可（进入后锁足）
- 每步限时 **45 秒**，超时清扫器**代走随机合法步**（不判负）。
- 走子后如无任何合法步 → 该方判负（`stuck`）。

## 6. 战斗（`resolveBattle`）

| 情形 | 结果 |
|---|---|
| 守方是 `qi` | 攻方胜，**夺旗 → 游戏结束**（win_reason `flag`） |
| 攻方是 `zha` | 同归于尽（含撞司令 → 触发亮旗；撞军旗 → 同归且夺旗） |
| 守方是 `lei` | 攻方是 `gong` → 工兵胜（只死雷）；否则同归于尽 |
| 其余 | rank 大者胜；同级同归于尽；rank 小者攻方亡、守方留 |

- 战斗后：胜者停在落点；同归于尽双方消失；攻方亡则守方原地不动。
- **阵亡棋子身份立即公示**（alive=false + revealed=true，双方阵亡托盘可见）。
- **交战暴露**：战斗中存活下来的一方（胜者/守方）从此对对手亮名（revealed=true）。
- **司令阵亡**（任意方式）→ 该方 `flagRevealed=true`，其军旗对对手亮名（revealed=true）。

## 7. 胜负

- `flag`：夺取对方军旗
- `stuck`：对方无任何合法步
- `eliminated`：对方全部棋子阵亡
- `forfeit`：对局中对方认输/离开；`waiting/layout/rps` 阶段离开 → 房间直接 `closed`（剩方收到关闭状态，可回大厅另开）

## 8. 房间生命周期

- `waiting`（创建）→ 对方加入坐满 → `layout`（300s）→ 双方 ready → `rps`（10s×≤3 轮）→ `playing`（45s/步）→ `finished` / `closed`。
- rematch（任一玩家发起，finished 后）→ 重置 `layout`（双方重新布阵），聊天与冷却保留（carryChat）。
- 超时兜底三合一清扫（1s Timer）：layout 到期代随机布阵 + 就绪推进；rps 到期代出拳；playing 到期代走随机合法步。
- 写路径懒推进带请求者放行（防 422 软锁）；`touchSeenAt` 心跳不 bump version。
- 无 saved 存档（代走机制保证不卡局）。

## 11. pieces JSON schema

`junqi_rooms.pieces` 存双方 50 子（含阵亡）：

```json
[
  {"side": "red", "rank": "gong", "r": 8, "c": 0, "alive": true, "revealed": false}
]
```

- `r/c` 为**绝对显示坐标**（r 0..11，c 0..4）；红方子 r∈[6,11]，蓝方子 r∈[0,5]
- **协议坐标约定**：客户端→服务端（布阵/走子）一律传绝对坐标；蓝方座位客户端在本地做 180° 旋转（screen↔absolute：r'=11−r，c'=4−c，转轴为中心点，保持行营斜线关系），服务端不感知座位朝向
- `alive=false` 的子保留原坐标，`revealed` 恒为 true（阵亡即公示）
- 序列化视角裁剪（serialize(viewerRole)）：
  - 己方子：全字段可见
  - 对方存活子：`revealed=true` 才带 `rank`；否则**不带 rank 字段**（前端按背面渲染）
  - 对方阵亡子：带 rank（托盘公示）
  - `ready`（layout 期）：对方只给 `{ready: bool}`，不给阵型
